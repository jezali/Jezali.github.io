## 3. Technical architecture

### Stack
- Rust (stable) + `wasm-bindgen` + `web-sys` + `js-sys`.
- **No heavy UI framework.** Prefer direct DOM/Canvas via `web-sys`, or at most a tiny, justified dependency. If you pick Yew/Leptos/Dioxus, explain why in one sentence and prove the size budget still holds.
- Build with **Trunk** (preferred) or `wasm-pack`. Provide the exact commands.
- **Local only for now.** Dev with `trunk serve`; check the production build with `trunk build --release` plus any static file server. Keep the output a plain static folder so it can be deployed later to GitHub Pages or a custom domain without changes. Include a GitHub Actions deploy workflow only as an optional file that is disabled by default (`workflow_dispatch` trigger only).

### Size and speed budget
- Total transferred (HTML + CSS + JS glue + `.wasm`) **under ~150 KB gzipped**, excluding the avatar.
- `Cargo.toml` release profile: `opt-level = "z"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`. Run `wasm-opt -Oz`.
- Avoid pulling in `regex`, `serde_json` with heavy features, `chrono`, `rand` with large defaults, etc. Use `js_sys::Date`, `js_sys::Math::random`, and `serde` only if needed (or parse the few JSON fields by hand via `js_sys::JSON`/`Reflect`).
- First paint must not wait on WASM: ship real HTML/CSS content so the page is readable instantly, then WASM progressively enhances it (canvas background, terminal, data, easter eggs).
- Lazy-load anything non-essential. Use `<link rel="preload">` for the wasm and the font.
- **Fonts:** one monospace font, self-hosted as a subsetted `woff2` (e.g. JetBrains Mono, IBM Plex Mono, or Terminus-style), `font-display: swap`. No Google Fonts requests.
- No CSS frameworks, no icon fonts, no JS libraries. Inline SVG for the few icons.

### Animation performance rules
- Only animate `transform` and `opacity` in CSS. Never animate layout properties, `box-shadow` blur, `filter: blur`, or `backdrop-filter`.
- One `requestAnimationFrame` loop total, driven from Rust, **paused when the tab is hidden** (`visibilitychange`) and when the canvas is off-screen (`IntersectionObserver`).
- Canvas background: cap DPR at 1.5, cap to ~30 fps on mobile, small particle/trace count, no per-frame allocations (reuse buffers).
- Respect `prefers-reduced-motion: reduce`: disable canvas animation, glitch, and typing effects; show static final states.
- Provide an on-page toggle in the footer, `[fx: on/off]`, persisted in `localStorage`.

### GitHub data
- Fetch `https://api.github.com/users/Jezali/repos?per_page=100&sort=updated` from Rust via `fetch`.
- **Cache** the response in `localStorage` with a timestamp (e.g. 1 hour TTL) to avoid the 60 req/hr unauthenticated rate limit.
- **Fallback:** ship a build-time `repos.json` snapshot (generated by a small script or a `build.rs`/CI step) so the page works if the API fails or is rate-limited. Show a tiny `[cached]` / `[offline snapshot]` tag instead of an error.
- Show: repo name, description, primary language, stars, last-updated (relative, e.g. "3d ago"), link. Skip forks and archived repos by default. Pin/sort so C / embedded / STM32 / PCB-related repos appear first (match on language `C`, topics, or keywords like `stm32`, `hal`, `kicad`, `pcb`, `firmware`, `rtos`, `uart`, `spi`, `i2c`).
- Optionally show a language-breakdown bar built from the repos' primary languages (flat colors, no gradient).

## 4. Design system

### Palette: Gruvbox (dark, hard contrast variant)
Use CSS custom properties on `:root`. Flat fills only.

```css
:root {
  --bg0-hard: #1d2021;
  --bg0:      #282828;
  --bg1:      #3c3836;
  --bg2:      #504945;
  --bg3:      #665c54;
  --fg0:      #fbf1c7;
  --fg1:      #ebdbb2;
  --fg2:      #d5c4a1;
  --fg4:      #a89984;
  --gray:     #928374;
  --red:      #fb4934;
  --green:    #b8bb26;
  --yellow:   #fabd2f;
  --blue:     #83a598;
  --purple:   #d3869b;
  --aqua:     #8ec07c;
  --orange:   #fe8019;
}
```

- Background: `--bg0-hard`. Text: `--fg1`. Muted text: `--fg4` / `--gray`.
- **Primary accent: `--orange` (`#fe8019`)**, used consistently. `--aqua` is the "signal/online" color, `--yellow` is for rare secondary highlights, and `--red` is reserved for glitch/warning moments.
- This is cyberpunk through **restraint**: warm amber on near-black, like an old industrial terminal or a Blade Runner street sign, not neon pink/cyan overload.
- Provide a light variant? **No.** Dark only. (Optionally a `[theme: amber / aqua]` accent swap easter egg.)

### Typography
- Monospace everywhere.
- Handle "Jezali": large (clamp ~48-96px), regular or medium weight, letter-spacing slightly wide. It is the focal point.
- Everything else small: body ~14-15px, labels ~11-12px uppercase with letter-spacing.
- "Hossein Monjezi": ~12-14px, `--fg4`, normal weight.

### Look and feel
- Flat, hard-edged, 1px borders in `--bg2`/`--bg3`, square corners (0-2px radius max).
- Layout motifs from **PCB and datasheets**: thin trace lines connecting sections, pad/via circles at line junctions, silkscreen-style labels (`REF: J1`, `U1`, `R12`), pin-1 dot marker, board-edge outline, test-point labels (`TP1`).
- Section headers formatted like firmware/boot logs or register maps, e.g. `[ 0x01 ] ABOUT`, `[ 0x02 ] PROJECTS`.
- Generous whitespace, tight content width (~720-860px), mobile-first.

## 5. Anti-"AI slop" rules (strict)

Do **not** use any of the following:
- Gradients of any kind (especially purple-to-blue/pink), gradient text, gradient borders.
- Glow, neon bloom, `text-shadow` glow, heavy `box-shadow`, glassmorphism, blur, frosted panels.
- Floating blobs, orbs, aurora backgrounds, shimmering/shiny sweep effects, sparkles.
- Rounded soft cards with drop shadows, pill badges everywhere, emoji as decoration.
- Generic filler copy: "Welcome to my portfolio", "passionate developer", "crafting digital experiences", "innovative solutions". Write short, dry, specific, slightly self-deprecating engineer copy instead.
- Stock icon sets, stock illustrations, generated imagery.
- Perfectly symmetrical 3-column feature grids with icon + title + blurb.
- Excessive CRT effect. A **very subtle** static scanline overlay (opacity <= 0.04) is the maximum, and it must be a cheap CSS pattern, not an animated filter.

Do use:
- Hard 1px lines, hard pixel offsets (`2px 2px 0 var(--bg2)`) if a shadow is needed at all.
- Step-based animations (`steps()`) that feel mechanical/digital, like a terminal or a microcontroller, rather than smooth easing.
- Slightly imperfect, human details: a typo-corrected log line, a TODO comment, a blinking cursor, a `printf` debug line.

## 8. Motion and animation allowed

All animations must be consistent with the Gruvbox/cyberpunk-minimal identity and feel **mechanical, not shiny**:
- Boot log with line-by-line reveal (stepped).
- Blinking block cursor (`steps(1)`).
- PCB trace background on `<canvas>` drawn from Rust: thin 1px orthogonal and 45-degree traces in `--bg2`, a few "signal pulses" (small `--aqua` or `--yellow` dots traveling along traces at constant speed). Low density, ~30 fps cap, pause offscreen.

- Section reveal: simple opacity + 4-8px translate, stepped, triggered once by `IntersectionObserver`.
- Link hover: instant color/underline swap, no easing.

Nothing should loop heavily or draw attention away from the handle **Jezali**.
